# Fixture provenance

Every fixture in this directory is **synthetic**. This manifest is the
audit trail: what each file is, where every value comes from, and why
none of it is (or derives from) licensed rating content.

## The rule these fixtures exist to satisfy

The public repo ships **zero bureau- or carrier-derived rate content**
— no ISO loss costs, no rating-bureau factors, no filed carrier rates,
neither verbatim nor perturbed, in the tree or in its git history.
Real programs run through OpenRater only on the user's own box (e.g.
the local-only acceptance gate, `RATER_ACCEPTANCE_WORKBOOK`, which
reads a workbook path from the environment and is never committed).

## The Meridian fiction

"Meridian Mutual Insurance Company" is a fictional Nebraska carrier.
Its Shopfront BOP program was invented for this repository as the
reference artifact for the whole loop — filing → transcription →
workbook → build → quote — and doubles as the regression net.

- **Factors, rates, bands, tiers, eligibility rules:** invented from
  scratch in `docs/specs/examples/meridian-shopfront-bop/
  generate_workbook.py`. They are not perturbations of any real
  program; they were chosen to exercise engine constructs (towers,
  2-D matrices, an interpolated curve, endorsements, a clamp, a
  floor, compound gates), not to resemble market rates.
- **Geography:** the ZIP codes are real public Nebraska geography
  (ZIPs exist; their grouping into territories t1–t6 and every
  territory factor are invented).
- **Class codes:** `c101`–`c140` are an invented vocabulary with
  invented descriptions. They are not ISO, NCCI, NAICS, or SIC codes.
- **The filing** (`meridian_shopfront_bop_filing.pdf`) is generated by
  `generate_filing.py` from the same constants; every page footer
  states the carrier is fictional.

## How the fixtures are consumed

- **Deploy seed** — `deploy/overlay/openrater_deploy/seed.py` pre-loads
  every `*.plan.json` here on boot (`RATER_SEED_COLD_TEST`, default on
  in the deploy compose; `reset` restores pristine plans).
- **Oracle gate (CI)** —
  `frontend/src/integrations/meridianSeedFixture.verify.test.ts` runs
  the committed blob through the production projection + engine and
  asserts all 20 demo-book rows at their exact expected premiums and
  tiers, with the filing's first worked example ($1,898) additionally
  pinned as a literal.
- **Populated-migration class test** —
  `server/tests/test_migrations_populated.py` seeds these fixtures at
  the migration anchor and runs the current chain over them.

## Regenerating

Regeneration order matters — the filing writes the citation sidecar
the workbook reads, and the fixture captures the workbook's build:

```sh
cd docs/specs/examples/meridian-shopfront-bop
uv run --with reportlab --with openpyxl python generate_filing.py
uv run --with openpyxl python generate_workbook.py
uv run --with openpyxl python generate_demo_book.py
# then, with a fresh server + scoring service running (so the build
# report's vectors run), build the workbook and re-capture:
#   python scripts/plan_fixture.py export meridian-shopfront-bop-ne-2026 \
#       docs/fixtures/meridian-shopfront-bop-ne-2026.plan.json --db <db>
```

Timestamps inside the captured blob (`created_at` / `updated_at`)
reflect capture time; a re-capture diffs on them even when nothing
substantive changed. Regenerate the blob only when the program or the
substrate schema actually changes.
